## TASK D — Antigravity · endpoint diagnostico anomalie partner

**Branch:** `ag/diagnostics-partners` — **mai committare su `main`.**

### Perché serve
Lavorando sui 26 partner sono emerse anomalie ricorrenti nei dati. Oggi si scoprono solo
guardando a mano, partner per partner. Serve uno strumento che le trovi in dieci secondi,
oggi e fra sei mesi.

**Questo task NON corregge i dati: li segnala.** La correzione resta un'operazione umana
verificata. Motivo: sui dati partner un errore è silenzioso — produce record plausibili
mentre il sistema resta incoerente — mentre un endpoint che non funziona lo si vede subito.

### Cosa costruire
`GET /api/admin/diagnostics/partners` — restituisce, per ogni partner, l'elenco delle anomalie
rilevate, più un riepilogo aggregato.

Controlli da implementare (uno per regola, ognuno con il suo codice):

| Codice | Controllo |
|---|---|
| `PLAYLIST_URL_INSTEAD_OF_ID` | `youtube_playlist_id` contiene `http` o `watch?v=` invece di un ID playlist (che inizia per `PL`) |
| `PHASE_OUT_OF_SCALE` | `phase` non è in `F1…F7` né `LIVE` (es. `F9`) |
| `DEMO_RECORD` | record di test/seed presente tra i partner reali (es. id che inizia per `demo-`) |
| `EMPTY_OFFER` | `offerName` o `offerPrice` vuoti nell'hub |
| `HUB_STALE_VS_PARTNER` | `partner-hub.updated_at` più vecchio di `partners.updated_at` oltre una soglia (default 30 giorni) |
| `REVENUE_ZERO_WITH_ACTIVE_CONTRACT` | `revenue = 0` con contratto risultante attivo |
| `MISSING_SUBDOMAIN` | `systeme_subdomain` vuoto per un partner oltre F2 |

Risposta suggerita:
```json
{
  "generated_at": "…",
  "partners_checked": 26,
  "issues_total": 41,
  "by_code": { "PLAYLIST_URL_INSTEAD_OF_ID": 3, "PHASE_OUT_OF_SCALE": 4, "…": 0 },
  "partners": [
    { "id": "19", "name": "…", "issues": [ { "code": "PHASE_OUT_OF_SCALE", "detail": "phase=F9", "field": "phase" } ] }
  ]
}
```
