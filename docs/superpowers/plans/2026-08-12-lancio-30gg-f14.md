# Lancio 30 giorni F-14 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Trasformare F-14 da generatore dichiarativo di idee in un calendario di lancio ibrido, esattamente di 30 giorni, versionato e approvato con evidenze server-side.

**Architecture:** Un servizio puro definisce schema, normalizzazione e readiness del calendario. Il router `editorial_calendar` diventa l'unico ingresso per generazione, salvataggio, conferma partner e approvazione admin; le versioni vivono in una collection append-only e lo step canonico conserva soltanto il riferimento approvato. La UI partner modifica una bozza precisa, mentre l'admin approva o respinge la stessa versione.

**Tech Stack:** Python 3.11, FastAPI, Pydantic, Motor/MongoDB, pytest, React 19, Axios, React Testing Library, Jest/CRACO.

## Global Constraints

- La Partnership dura 12 mesi dalla data di pagamento.
- F-14 contiene esattamente 30 giorni unici e consecutivi.
- Ritmo standard: 4 contenuti principali a settimana, storie quasi quotidiane, 30 minuti al giorno per interazioni/outreach/DM.
- Modello ibrido: contenuti e DM -> masterclass -> live -> checkout; call solo di recupero.
- Prezzo stabile e bonus reale a scadenza.
- Nessuna CTA puo' puntare a URL o date inesistenti.
- `launch_calendar_approved` e' una policy governata da evidenze server-side.
- Generare non equivale ad approvare; rigenerare non sovrascrive versioni approvate.
- Partner e admin usano la guardia `require_partner_or_admin_for_partner`; approvazione finale solo admin.
- Italiano semplice, diretto e anti-fuffa.
- Non modificare il prompt di Matteo.
- Non toccare tracking ads, cicli Ottimizza, casi studio o rinnovi in questo piano: avranno piani separati.

```python
@dataclass(frozen=True)
class LaunchCalendarReadiness:
    ready: bool
    checks: list[dict[str, Any]]
    @property
    def failed_codes(self) -> list[str]:
        return [c["code"] for c in self.checks if not c["ok"]]

def normalize_launch_calendar(raw, start_date, live_date):
    days = sorted(raw.get("days") or [], key=lambda item: int(item["day"]))
    if [int(item["day"]) for item in days] != list(range(1, 31)):
        raise ValueError("Il calendario deve contenere esattamente i giorni 1-30")
    normalized = []
    for item in days:
        n = int(item["day"])
        normalized.append({
            **item,
            "day": n,
            "date": (start_date + timedelta(days=n - 1)).isoformat(),
        })
    if normalized[27]["date"] != live_date.isoformat():
        raise ValueError("La live deve coincidere con il giorno 28")
    return {**raw, "days": normalized, "start_date": start_date.isoformat(),
            "live_date": live_date.isoformat()}
```

`evaluate_launch_calendar` deve produrre check nominati per: 30 giorni, date consecutive, live al giorno 28, campi per giorno, URL HTTPS reali, routine organica, bonus/scadenza, conferma partner e approvazione admin.
